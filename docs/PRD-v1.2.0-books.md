# 词书体系扩展 —— 增量 PRD（v1.2.0）

> 本文档是 v1.1.1 基础上的**增量需求**，只覆盖「三本词书 + 词书切换」相关变更，不改动现有背词/测试/范文等已上线能力。

## 0. 项目信息

| 项 | 内容 |
| --- | --- |
| Language | 中文（简体） |
| Project Name | cet4words |
| 版本 | v1.2.0（versionCode 10200） |
| 形态 | 安卓 WebView 混合应用（HTML/CSS/JS 离线内嵌 + 纯 Java 壳） |
| 数据源 | kajweb/dict（CET4 完整 + CET6 完整）+ ECDICT 词频（筛核心词） |

**原始需求复述**：一次做全三本词书 —— ① 四级核心（约 1500–2000 高频，先背高频）② 四级完整（现有 4522 词）③ 六级完整（kajweb/dict CET6，约 4000+ 词），并支持用户在 App 内切换当前学习词书。

## 1. 产品定义

### 1.1 Product Goals

| # | 目标 |
| --- | --- |
| G1 | 一次装齐三本词书（核心/完整/六级）并支持 App 内切换，切换**不丢任何一本的进度**。 |
| G2 | 默认「先背高频」：四级核心词书（1500–2000 高频）成为新用户默认学习入口。 |
| G3 | 老用户升级 v1.2.0 后，原有四级学习记录 **100% 保留**并自动归入「四级完整」，零重学。 |

### 1.2 User Stories

| # | 场景 | 用户故事 |
| --- | --- | --- |
| US-1 | 词书切换 | As a 备考四六级的学生，I want 在首页一眼看到当前词书并一键切换，So that 我随时在「四级核心/四级完整/六级完整」间切换而不丢各自进度。 |
| US-2 | 三本词书 | As a 学生，I want 三本词书（四级核心 2000 高频、四级完整 4522、六级完整 4000+）一次装好，So that 我按「先高频、后完整；先四级、后六级」规划备考。 |
| US-3 | 进度隔离 | As a 学生，I want 每本词书的背词进度与复习计划互相独立，So that 我学六级时不会打乱四级的复习节奏。 |
| US-4 | 老数据平滑迁移 | As a 老用户，I want 升级后原有四级学习记录完好无损，So that 我不必从零重背。 |
| US-5 | 生词本跨书 | As a 学生，I want 生词本跨词书统一收藏，So that 我在任意书里标记的难词都能集中攻克。 |

## 3. 关键交互说明

### 3.1 词书切换入口（决策点 D1）

- **入口 A（主）**：首页 Hero 卡顶部新增「当前词书」胶囊（如 `四级核心 ▾`），点击进入词书选择页。
- **入口 B（次）**：设置页新增「词书」分区，展示当前书 + 「切换词书」按钮，复用同一选择页。
- **不新增底部导航 tab**：切换是低频动作（数天/数周一次），不值得占用常驻入口；Hero 是首页最高视觉权重位，最适合承载「当前在学哪本书」。

### 3.2 词书选择页（page-books）

- 全屏二级页，顶部返回键（复用现有返回键逻辑）。
- 列表三行：每行显示「书名 + 词数 + 当前书进度（已学 N / 总数）+ 待复习 N」；当前书高亮 + 选中标记。
- 点选任一行 → 写入 `current_book` → 切回首页并 `renderHome()` 刷新。

### 3.3 首页联动

- Hero 内「今日新词进度 / 待复习数」、底部三个统计小卡全部按当前词书计算。
- 打卡（连续天数）仍全局一天一次，不受切书影响。

## 4. 数据决策点（5 项，含建议与理由）

### D1 词书切换入口放哪

- **建议**：首页 Hero 区显示当前词书名 + 点击进词书选择页；设置页放次级入口；**不占用底部导航**。
- **理由**：低频操作不配常驻 tab；Hero 权重最高、认知最顺（"今天背哪本"直接可见）；设置页兜底保证可达性。

### D2 进度如何隔离

- **建议**：
  - 背词进度（progress）+ 复习队列 + 学习/复习计数 → **按词书完全独立**。
  - 连续打卡（streak）→ **全局唯一**（今天在任意书学 ≥1 词即打卡），避免"三本书三个连续天数"的困惑。
  - 生词本（notebook）→ **全局共享**（跨词书统一收藏）。
  - 测试出题 → **从当前词书出题**（已学词优先，不足从当前词书全库补），不跨书。
- **理由**：四六级是两条独立备考线，混排会污染复习队列与统计；生词本是"我的薄弱词集合"，跨书共享更符合直觉且实现简单（词条统一从全局索引解析）；测试"学什么测什么"保持一致。

### D3 老数据迁移

- **现状**：`cet4.progress` 是全局 word→record 扁平对象（四级 4522 词），`cet4.stats` 是全局统计。
- **建议**：引入 `cet4.meta`（`schema_version` + `current_book`），启动时做一次性迁移：
  1. 把旧 `cet4.progress` 整体写入 `四级完整(cet4_full)` 的 progress。
  2. 把旧 `cet4.stats` 的累计/计数写入 `cet4_full` 的 stats；streak 字段迁移到全局。
  3. `四级核心`、`六级完整` 初始为空。
  4. 用 `schema_version=2` 标记已迁移，保证幂等（重启不重复执行）。
  - `cet4.notebook` / `cet4.settings` / `cet4.quiz_history` / `cet4.essay_progress` 保持全局原样。
- **理由**：老数据语义上就是"四级完整"书的数据，归入它最平滑、零丢失；核心/六级从零开始，符合"先背高频"的增量意图。

### D4 四级核心词筛选标准

- **建议**：从现有 4522 词按**词频排序取前 N**（N 默认 2000，即"1500–2000"上限，构建脚本可配）。数据源优先 **ECDICT 的 `frq` 词频字段**：按 word 精确匹配 4522 集合，按 frq 升序（高频在前）取前 2000；无 frq 的词排到队尾。产出**词单文件** `cet4_core.js`（只存有序 word 数组），词条内容复用 `cet4.js`。
- **理由**：词频是"高频词"最客观的代理指标；复用现有词条保证核心词与完整书内容一致、质量可控；只存词单 + 复用词条 ≈ APK 体积几乎不增。
- **备选**：若无 ECDICT 访问，改用 exam-data/CETVocabulary 5278 词频排序表（按表顺序过滤出属于 4522 集合的词取前 2000）。
- **校验要求**：架构侧写 `tools/build_core.py`，校验"核心词数 ∈ [1500,2000]"且"每个核心词都能在 cet4.js 命中"。

### D5 每日新词量 & 复习计划

- **建议**：**每本词书独立队列**。`daily_new` 仍是设置页一个全局偏好值（如 20），但按词书各自计数——用户同一天可在每本书各学 20 个新词、各有各的待复习队列；切换后首页展示当前书的进度/待复习。打卡仍全局一天一次。
- **理由**：独立队列才能兑现"四六级并行互不干扰"的隔离目标；单一偏好值避免设置页复杂化；全局打卡保留坚持激励。

## 5. 数据模型建议（给架构师）

```
cet4.meta          = { schema_version: 2,
                       current_book: 'cet4_core' | 'cet4_full' | 'cet6_full',
                       migrated_from_v1: bool }
cet4.books         = {
   cet4_core: { progress: {word: rec}, stats: {total_learned, total_reviewed, daily_new_count, daily_review_count} },
   cet4_full: { progress: {...}, stats: {...} },
   cet6_full: { progress: {...}, stats: {...} }
}
cet4.stats         = { streak_days, total_checkin_days, last_checkin_date }   // 全局打卡
cet4.notebook      = {word: {added_at}}       // 全局共享，保持
cet4.settings      = {accent, daily_new, theme}  // 全局，保持
cet4.quiz_history  = [...]                     // 全局，保持（P1 建议补 book_id）
cet4.essay_progress = {...}                    // 保持
```

- 数据文件：`cet4.js`（四级完整词条，保持）、`cet4_core.js`（有序词单）、`cet6.js`（六级完整词条）。
- 词书注册表：`{cet4_core: 四级核心/约2000, cet4_full: 四级完整/4522, cet6_full: 六级完整/约4000+}`。
- `Words` 模块改造为：全局词条索引（三书合并）+ 按词书取 word 列表；`SRS.dueWords/newWords`、`Quiz.sampleWords`、`Stats` 计数均接受/读取 `current_book`。

| Q5 | 测试是否严格"仅当前词书"？ | 建议是（避免四六级选项混排）；是否提供"全库"开关需拍板。 |
